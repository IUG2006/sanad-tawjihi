# Screen Inventory — Sanad Tawjihi

**Status:** MVP functional inventory; not a visual design  
**Route notation:** Suggested route patterns for UX and product alignment, not an implementation contract. IDs are stable references for discussion.  
**Roles:** G = guest, S = signed-in student, A = admin. Shared content always respects selected region and stream.

## Priority key

- **Core:** Required for the end-to-end study, exam, wallet, or admin MVP.
- **Supporting:** MVP support, account, recovery, sharing, or installation screen/action.
- **Future:** Explicitly out of MVP; listed for boundary clarity only and not included in MVP navigation.

## Navigation and route summary

- Student/guest primary: `/` → `/curriculum` → `/quiz/...`; `/exams`; `/mistakes`; `/account`; `/wallet` (signed in).
- Authentication preserves requested destination, region, stream, and selected quiz/exam context when possible.
- Admin is a separate protected route family: `/admin/login` → `/admin` → `/admin/topups` and `/admin/content`.
- Suggested patterns are placeholders; route hierarchy and required screen states are the contract, not exact URL syntax.
