# مخططات وتحليل نظام «سند توجيهي»

## الغرض ومصادر الحقيقة

تجمع هذه الملفات تحليلاً بصرياً لمتطلبات النسخة الأولية (MVP)، اعتماداً حصراً على:

- [وثيقة المتطلبات PRD](../PRD.md)
- [تدفق المستخدم](../user-flow.md)
- [مخطط الكيانات والعلاقات ERD](../ERD.md)
- [تعريف قاعدة البيانات DBML](../database.dbml)

إذا اختلف تمثيل مفاهيمي في هذه المخططات مع تفصيل تخزين أو قيد، فـ ERD وDBML هما مرجع بنية البيانات، وPRD هو مرجع السلوك والنطاق التجاري. لا تمثل المخططات بنية تقنية مختارة؛ فالـ PRD لم يحسم إطار التطبيق أو مزود قاعدة البيانات.

## كيف تتكامل المخططات؟

1. يضع **نموذج المجال** مفردات المنتج: الطالب، المسار والمنهاج، السؤال، الامتحان، النقاط، والشحن.
2. يحدد **مخطط حالات الاستخدام** من يستخدم هذه المفاهيم وما الوظائف المتاحة للزائر والطالب المسجل والمدير.
3. يقسم **مخطط النشاط** القرارات ومسارات الأعمال إلى ثلاثة أقسام: رحلة التدريب، وطلب الشحن ومراجعته، وبدء الامتحان وتسليمه.
4. يوضح **مخطط التسلسل** ترتيب التفاعل بين الطالب وتطبيق الويب والخادم وقاعدة البيانات وبوت تيليجرام في تشغيل امتحان.
5. يضبط **مخطط الحالات** دورة حياة محاولة الامتحان، كما تصفها حالات DBML وقواعد المؤقت والتسليم في PRD.
6. يحول **مخطط الفئات** مفاهيم المجال إلى تصميم أكثر تفصيلاً مع تمييز الخصائص المشتقة عن الحقول المخزنة.

## حدود التحليل ونقاط تحتاج حسمًا

- لا يظهر ولي الأمر ممثلاً في مخطط الاستخدام: يذكره PRD ضمن الجمهور المستهدف، لكن لا يعرّف له صلاحية أو تفاعلاً ضمن الأدوار وتدفق MVP.
- `quiz_attempts` مطلوب: تحفظ ملخص محاولات كويزات الدروس والوحدات فقط، ويخصم سعر الكويز المدفوع لكل محاولة. لا تحفظ إجابات الكويز المفردة على الخادم؛ تحفظ محاولات الزائر المجانية محلياً.
- أول درسين مجانيان بحسب ترتيب الوحدة؛ `is_free` قيمة مشتقة لا تُخزّن، ويجب أن يكون `order_index` فريداً داخل الوحدة.
- لكل فرع ثلاثة سجلات مواد مستقلة: الرياضيات واللغة الإنجليزية واللغة العربية؛ المجموع ستة سجلات بمحتوى منفصل.
- يقفل الخادم المحاولة عند `ends_at` بالحالة `expired` قبل فحص أي طلب بدء جديد؛ فلا تمنع المحاولة المنتهية محاولة جديدة. تستأنف المحاولة النشطة للنموذج نفسه دون خصم أو إنشاء محاولة أخرى. تحفظ إجابات الامتحان عند وصولها، ويحتسب آخر اختيار وصل قبل `ends_at`.
- عند فشل تحميل أسئلة الامتحان، تلغى المحاولة وتُرد النقاط فقط إذا أُنشئت في طلب البدء الحالي ولم تكن لها إجابات محفوظة. فشل التحميل لمحاولة مستأنفة أو لها إجابات محفوظة يعرض خطأ ويسمح بإعادة المحاولة دون إلغاء أو استرداد.
- الحالات `in_progress` و`completed` و`expired` و`cancelled` تعكس دورة المحاولة في PRD، مع قيد محاولة نشطة واحدة للمستخدم ونموذج الامتحان.
- يذكر PRD معالجة انقطاع الاتصال أثناء الامتحان واستمرار مؤقت الخادم، لكنه لا يحسم جميع تفاصيل تزامن التسليم عند انتهاء الوقت أثناء غياب الاتصال.
- يتطلب التدفق اختيار الفرع الدراسي، بينما حقل `users.stream` قابل للفراغ في DBML. يلزم تأكيد هل الاختيار إلزامي عند إنشاء الحساب.
- إدارة المحتوى ومراجعة الشحن موثقتان على أنهما بيد Admin؛ لم يُفترض وجود دور منفصل لمعلم أو ولي أمر.
- لا يفترض التحليل دمج المصادقة أو المدفوعات كخدمات ذات تصميم تقني، باستثناء Google OAuth وبوت تيليجرام اللذين يذكرهما PRD صراحة. لا يوجد تكامل آلي مع مزودي الدفع في MVP.

## التحقق

تتضمن كل وثيقة غرض الرسم ومصادر المتطلبات وشرحاً عربياً وافتراضات وأسئلة مفتوحة وملاحظات اتساق. التعددية تعكس العلاقات الموثقة في ERD/DBML؛ وأي قيد لا تفرضه المصادر معروض كسؤال مفتوح أو اقتراح، وليس كحقيقة.
